Selected work

Async task-queue offload service

Python · Flask/Gunicorn · multiprocessing — sole author

Design compilation is CPU-heavy and was blocking the main application server. I built a worker pool that pulls tasks from a shared queue and runs each as a sequential multi-stage pipeline, while many tasks proceed in parallel across the pool. Workers spawn on demand.

Most of what the service knows came from production failures. It emits per-stage timing because throughput regressions were otherwise invisible. It monitors memory because an out-of-memory condition once triggered a respawn storm that took the whole pool down. And it isolates failures so one bad job can't cascade — after a race-condition deadlock on shared state under concurrent dequeues.

In-browser 3D point-cloud engine

Vanilla JavaScript · Three.js · custom binary codec

Generating engraving geometry meant a round trip to a GPU server for every edit. I moved four of six generation paths into the browser, which took per-edit latency from a 1–3 second server round trip to instant.

That required decoding 16-bit depth images the browser won't decode natively, so I wrote a 16-bit PNG decoder from scratch with zero dependencies — inflate, unfilter, and bit-depth handling — plus a compact binary format for the point data and depth-aware layered sampling. Editing happens in place in a Three.js viewport.

Camera-to-machine calibration pipeline

Python · OpenCV · WebAssembly

A camera sees pixels; the machine moves in its own internal units. Bridging them is a calibration problem: detect printed ChArUco markers and grids at sub-pixel accuracy, fit curves, then solve a RANSAC homography mapping 225 grid points into real-world millimetres — RANSAC because a handful of detections are always wrong and a least-squares fit would quietly absorb them.

The pipeline also stitches many overlapping frames into one image, correcting for alignment, uneven lighting, and noise. I compiled the detector to WebAssembly so the same code runs in the browser.

Toolpath optimiser

Python · parallel C++ · kd-tree

An engraving job is thousands of disconnected marks, and the machine spends much of its time travelling between them. Ordering those moves well is a travelling-salesman problem. I implemented a solver with kd-tree nearest-neighbour lookup and grid-based partitioning for very large point clouds, in Python and parallel C++.

It cut engraving time by 72% in exchange for 7% more processing time — a trade worth making, since the machine is the bottleneck and the CPU is idle anyway.

Synchronous Flask → async FastAPI migration

Python · FastAPI · Socket.IO · asyncio — serves 500+ users

I drove the platform's move to an async architecture, building the new codebase from the ground up: modular device and client event handlers, an async cloud integration layer, a MySQL/SQLModel data layer, and OAuth login.

The interesting work came after. Async is unforgiving about blocking calls, and I traced event-loop starvation to synchronous cloud I/O more than once. Fixes included moving those calls off the loop, throttling a device probe so one unresponsive machine couldn't stall the server, and adding per-device locks and reentrancy guards so concurrent operations stayed safe.

Multi-server coherent cache

Python · asyncio · MySQL

A fleet of web servers each needed fast access to device state that lived in MySQL, without every request paying a round trip. I built an asyncio-locked in-memory cache with conditional write-through that skips no-op writes, fetch-on-miss fallback, an offline-authoritative mode for disconnected operation, and fire-and-forget cross-server invalidation so the fleet stays coherent.
